## 1. 🔴 关键发现：共享背景的光斑与实验间距**几何不匹配**

目标 20±3 μm 时，25 个候选**全部被否**（22 个过切 + 3 个覆盖不足）。

逐候选的横向行为（N=1）：

| h (μm) | 均值 (μm) | 最大 (μm) | **覆盖** | 过切 | 漏加工 |
|---|---|---|---|---|---|
| 2.0 | 24.27 | 206.65 | **23.9 %** | 17.9 % | 81.6 % |
| 4.0 | 7.19 | 145.15 | **12.8 %** | 8.3 % | 91.0 % |
| 10.0 | 1.13 | 69.32 | **4.9 %** | 1.9 % | 97.0 % |

**根因**：共享实验背景的 1/e² 光斑半径 = **0.874 μm**（直径 1.75 μm），
而实验间距是 **2–10 μm** —— **扫描线之间根本不重叠**。
画出来是一组**分离的沟槽**，不是连续面；76–95 % 的表面完全没被加工到。

这不是判据太严，是几何事实：

```
线间距 2 μm  >  光斑直径 1.75 μm   →  相邻扫描线不重叠
```

### 这解释了 C3 的 43 % 误差

C3 反推时用共享背景（0.874 μm）去拟合实验深度，二者不自洽 ——
**实测数据很可能来自另一套光学**（更大光斑、扫描线重叠），
而共享背景的 0.874 μm 只能打出分离沟槽。

这与任务书 §1 的提醒一致：*"上游算例保留它实际运行的工况…不能仅通过重写元数据变成上述实验"*。
**同理，共享背景也不能仅通过"确认适用"就套到这批 DOE 数据上。**

### ⚠️ 需要确认的问题

**共享背景的 0.874 μm 光斑，是否真的用于产生这四份 CSV 的实验？**

- 若是 → 那些"平均深度"其实是**沟槽内的平均值**，不是面加工深度；
  且 h/N 规划在这个光斑下没有连续面的可行解。
- 若否（实验用的是更大光斑，如 ZrO₂ 卡记录的 16 μm）→ 需要更正共享背景的光学项。

这个判断我做不了，需要你确认。

## 2. ⚠️ 标定过拟合（训练变好 ≠ 模型更可信）

```
a = 0.3207
训练 MAE  10.657 → 7.996 μm   （变好）
留出 MAE   3.648 → 7.020 μm   （变差）
```

**训练集变好、留出集变差**是典型过拟合信号。原因：

1. 样本太小（20 训练 / 4 留出）；
2. 基线本身有 43 % 误差，"用有偏基线 + 单参数纠偏"结构上不可能同时满足所有工况；
3. 单参数 `a` 是全局比例，而实际误差是**工况相关**的。

按任务书 §5.3 的要求，这里**如实报告实际残差**，不靠放宽界面掩盖模型不足。
正确的下一步是**按更细的窗口分组标定**（按频率或脉宽分组各自拟合 `a`），
而不是继续调大/调小全局 `a`。

## 3. 实现要点（本轮新增 C5）

`src/ufdemo/planning.py` 增加：

- `evaluate_candidate()` —— 生成路径 → **同一套已标定求解器** → 统计 → 判可行
- `plan_for_target()` —— 枚举 h/N，筛可行，按**理想时间 → 深度均匀性**排序

关键约束（都写进代码）：

1. **每个候选都真的跑求解器**（有测试钉住：25 个候选 25 个有数值结果）
2. **规划与标定共用同一条装配路径** —— 有测试对比 `evaluate_candidate`
   与 `predict_mean_depth` 在同一 (h,N) 上的深度必须**完全相等**（`rel=1e-9`）
3. **无可行方案时返回原因**，且区分「都太浅」/「都太深」/「横向约束不满足」
4. **质量信息分两类**：标量深度误差（实验证据）vs 覆盖/过切/均匀性（模型预测）；
   notes 里明写"未导入实测高度图时不构成二维形貌验证"
5. **焦点 Z 恒为 0**（所有候选，含多遍）—— 有测试钉住

### 测试抓到的一处接口不一致（已修）

`recommended` 是按时间排序后的第一项，而 `feasible_candidates` 用的是**原始顺序**
→ 界面上的「推荐」和表格第一行**对不上**。
已抽出统一排序键 `_rank_key`，并加不变量断言 `recommended is feasible_candidates[0]`。
