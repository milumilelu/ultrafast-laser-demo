# ADR-0017：按**超阈值半径**开窗（窗口半径策略，默认关闭）

* 状态：已采纳｜日期：2026-09-15｜批次：L

## 背景

用户报告：界面「规划与结果」在**域 400 µm / 加工区 200 µm / dx 0.5 µm** 下给出
「25 个候选预计 279,600 个事件，估算耗时约 65.2 分钟」的警告，要求查这个性能瓶颈，
并期望「改成真正的局部更新（O(patch) 而不是 O(grid)）」。

### 第一次诊断是错的，先更正

最初据 `域 100/200/400 µm → 1.6 / 14.2 / 22.2 s` 断言
「格数 ×4 → 成本 ×9 ⇒ 存在与网格大小成正比的 per-event 全局开销」。
**该结论被对照实验推翻**：把 `geometry_feedback` 换成 `fixed_geometry`
（离焦恒 0 ⇒ 光斑恒 1.33 µm ⇒ 窗口仅 ~250 格）：

| 域 (µm) | 网格 | µs/事件 |
|---|---|---|
| 100 | 40,000 | 131 |
| 200 | 160,000 | 132 |
| 400 | 640,000 | 138 |

**网格涨 16 倍，单事件成本只涨 5%** ⇒ 不存在隐藏的 O(网格) 代码路径。
当初看到「超线性」是因为窗口被网格**钳制**（域越小钳得越狠），
外加 40k→160k 跨 L2 缓存的次要效应。

### 真实成本模型

```
成本 ≈ 0.06 µs × 窗口格数        # 完全由窗口大小决定
```

而窗口大是 `axial_defocus` 的**自增强回路**：

| 环 | 实测值 |
|---|---|
| ① 深度 | 一趟烧到 **132 µm**（δ=3.6525 µm × ln(F_peak/F_th=1231) = 25.99 µm/第一炮） |
| ② 离焦 | 132 µm ≫ zR=4.47 µm ⇒ **30 倍** |
| ③ 光斑 | 1.33 µm ⇒ **39 µm** |
| ④ ε 窗口 | `cut_radius(w, 1e-8) = 3.035w` ⇒ 直径 **237 µm**（吃满 200 µm 域） |

（深度 ≫ zR 不是新问题：progress.md 的 C5/C6 已记录「覆盖好的候选深度 ≥30 μm、无可行解」，
C3 也标明 δ=3652.5 nm 是「**初值级别，非可用模型**」。）

**关键事实**：窗口里**超阈值**（对去除真有贡献）的格子只占 **0.8%**。
事件 1 窗口 64 格；事件 100 之后窗口 34,000 格吃满网格，其中超阈仅 ~340 个。

## 决定零（补记）：回退 `5fa5630` 的「局部迭代窗口」—— 那是回归

`5fa5630` 把窗口改成用**窗口内**的起伏定尺寸。实测证明它**会静默漏算**：
光束脚下恰好是未加工的平地、而 20 µm 外是 ~95 µm 深的坑时，窗口内跨度趋近 0
⇒ 窗口缩到 4 µm ⇒ 把离焦 ``u* = A/e`` 处（ablating 半径**峰值** 19.95 µm）那段
**仍然能烧蚀**的环带整段切掉。

域 200 / 加工区 100 / dx 1.0、h=6/N=1、事件 40 实测：局部窗口 8×9 只算出 **20** 个非零格，
真实是 **87** 个。误差沿事件累积 ⇒ 25 个候选里 15 个深度不一致
（N=1 恰好不触发，所以当时的 A/B 抽检漏掉了它）。

⇒ 默认策略**恢复「全网格轴向跨度」口径**，与回归前提交 `e79892a` **逐位一致**
（最大绝对差 `0.000e+00`）；超阈值策略改用下面**与深度无关**的严格上界，
二者**全部 25 个候选逐位相同**。

## 决定一：按**与深度无关的严格上界**开窗，而不是 ε 尾部截断半径

阈值型响应核（`log_fixed`、`TabulatedEventLaw` 的上界拒绝路径等）在
``F <= F_th`` 处返回**恰好 0**。记 ``A = F_peak(s=0)/F_th = 2E/(π w0² F_th)``，
某格自身离焦 ``u = (w_cell/w0)² >= 1``，该格处

```
F(r)/F_th = (A/u)·exp(-2r²/(u·w0²)) > 1  ⟺  r² < w0²·f(u)/2,   f(u) = u·ln(A/u)
```

``f`` 在 **``u* = A/e``** 处取唯一极大值 ``f_max = A/e`` ⇒ 对**任意** u 有

```
r_max = w0 · sqrt(A/(2e)) · margin      ← 与当前深度无关
```

* ``A <= 1`` ⇒ 半径 0 ⇒ **任何格子都不可能超阈值**，窗口取空；
* ``margin`` 默认 **1.25**（1.0 已由严格不等式保证，余量吸收网格离散与斜入射平移）。

⚠️ **为什么不能用「窗口内最深点的 F = 阈值半径」**：``r(u)`` 对 u 非单调，
在深孔末期（u 远大于 u*）它小于 ``w0·sqrt(A/(2e))`` —— 这正是决定零里的回归成因。

### 为什么这**不改变任何去除量**

半径之外每个格子的能流都 < 阈值，响应律给出的增量本来就是 0。
所以切断它们**不影响**任何物理量 —— 用 ``np.array_equal``（不设容差）守住。

## 决定二：代价必须**可追踪**，且**默认关闭**

被切掉的格子仍会被计入**剂量观测量**：`cumulative_fluence`、`illumination_count`、
估计截获能量。启用后它们的统计范围**会缩小**，因此：

1. `fluence_ledger.threshold_window` 新增：`enabled` / `threshold_internal` /
   `margin` / `events` / `window_cells_total` / `tail_window_cells_total` /
   `cells_skipped_fraction` / `collapsed_events`；
2. `fluence_ledger.window_radius_policy` 回显实际生效的策略；
3. 收尾警告**改口径**：启用时不得再说「能流尾部超出计算域」，而要说
   「这部分能流**低于响应阈值**、对去除贡献恰好为 0，不是域截断、也不是热损失」。
   两种口径的文案分离，由 `window_policy` 分支决定；
4. **默认 `"tail_epsilon"`** ⇒ 既有算例零影响；只有显式配置才启用。

## 决定三：不静默退化

* 策略取值非法 ⇒ `CONFIG_INVALID`；
* 请求 `above_threshold` 但响应核**没有声明** `threshold_internal` ⇒
  solver **回退**到 `tail_epsilon` **并写警告**（绝不假装收缩已启用）；
* `BeamOptions` 层缺阈值 / 余量 < 1 ⇒ 直接抛错；
* 分组批量路径（`mode=grouped`）不支持该策略 ⇒ 写警告说明本次仍按 ε 窗口。

## 不做什么

* ~~不接界面~~ —— **已接**（规划页下拉 + 分口径预估 + planner/接口透传）；
* **不动标定**：δ / Fth 属 C3，深度回到合理量级后窗口自然变小 —— 那是物理侧的事，
  与本决定正交（本决定在**任何**深度量级下都成立）；
* **不改 `axial_defocus` 语义**：焦点固定在初始表面、按当前高度算离焦是 C1 定的。

## 实测收益（1,040 事件，`axial_defocus`）

| 算例（事件数） | 既有 | 超阈开窗 | 提速 | 高度场 | 裁掉窗口格 |
|---|---|---|---|---|---|
| 域 200 / 加工区 100 / dx 1.0（1,040） | 1.40 s | 0.24 s | **5.9×** | 逐位一致 | 92.88% |
| 域 400 / 加工区 100 / dx 0.5（1,040） | 21.91 s | 1.34 s | **16.3×** | 逐位一致 | 95.34% |
| **域 400 / 加工区 200 / dx 0.5（4,080，界面参数）** | **77.58 s**（19.0 ms/事件） | **3.21 s**（0.79 ms/事件） | **24.2×** | 逐位一致 | 95.41% |

按界面那批 279,600 个事件线性换算：**约 88 分钟 → 约 3.7 分钟**
（决定零之前贴出的 35× / 1.9 分钟是**用回归版窗口**测的，作废）。

规划层面（25 个候选，域 200 / 加工区 100 / dx 1.0）：**158.0 s → 33.8 s（4.7×）**，
且 25 个候选的 `mean_depth_um` / `max_depth_um` / `coverage_fraction` / `depth_std_um` / `status`
**全部逐位相同**。

  「ablating 半径非单调的回归测试」「N>=2 候选逐位一致（当初失败过的 h=2/N=2）」

* 验收清单 **181 通过 / 0 失败 / 2 未运行**；界面 24-0；端到端 13-0；
